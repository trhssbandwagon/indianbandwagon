## Architecture

This is a **Next.js 16 / React 19** app using **Prismic CMS** as the content layer, with **Tailwind CSS v4** and **shadcn/ui** (Radix UI) components.

### Prismic Content Model

All content is managed in Prismic. The repository name is `indianbandwagon` (set in `prismic.config.json`). Custom types and their routes:

| Custom Type | Route | Notes |
|---|---|---|
| `homepage` | `/` | Fetched as singleton |
| `page` | `/:parent?/:uid` | Supports nested pages via `parent` field |
| `post` | `/blog/:uid` | Blog posts |
| `fundraiser` | `/fundraisers/:uid` | Fundraiser pages |
| `settings` | singleton | Site metadata, analytics IDs, org details, privacy toast message |
| `layout` | singleton | Nav logo, navigation links, CTA link |

### Slice Machine

Slices live in `src/slices/`. Each slice directory contains `index.tsx`, `model.json`, `mocks.json`. **`src/slices/index.ts` is auto-generated by Prismic — never edit it manually.** The `bun dev` command runs the Prismic type syncer in watch mode alongside Next.js.

### Routing

- `src/app/page.tsx` — homepage (`getSingle('homepage')`)
- `src/app/[...path]/page.tsx` — all nested `page` type documents; extracts `uid` from the last path segment; uses `fetchLinks: ['page.title']` to resolve breadcrumb labels from the parent page
- `src/app/blog/[uid]/page.tsx` — blog posts
- `src/app/fundraisers/[uid]/page.tsx` — fundraisers
- `src/app/slice-simulator/page.tsx` — Prismic slice previewer

### Key Patterns

**Page title suppression**: The `[...path]/page.tsx` renders an H1 from `page.data.title` _unless_ the first slice is a `hero` — in that case the hero owns the visual heading.

**Breadcrumbs**: Rendered on `[...path]` pages only (not homepage, blog, fundraisers). Requires `fetchLinks: ['page.title']` to display parent page names rather than slugs.

**Slice context**: All `SliceZone` calls pass `context={{ page: searchParams.page }}` so slices that paginate (e.g. `ContentIndex`) can access the current page number.

**Caching**: In production, Prismic responses use `force-cache` tagged `prismic`. The `/api/revalidate` POST endpoint calls `revalidateTag('prismic')` for Prismic webhook-triggered ISR. In dev, responses revalidate every 5 seconds.

**Analytics**: GA4, Microsoft Clarity, and Facebook Pixel are only loaded when `NEXT_PUBLIC_VERCEL_ENV === 'production'`. Consent state is stored in `localStorage` under `cookie-consent` and `has-seen-privacy-notice`. The `OptOut` slice lets users revoke consent.

**Structured data**: JSON-LD is injected on every page — `Organization` + address graph in the root layout, `WebPage` on `page` documents, `BlogPosting` on posts. Organization fields are populated from the `settings` singleton.

### Layout Components

- `Section` (`src/components/layout/Section.tsx`) — wraps content with optional padding and a `width` prop (`full` | `2xl` | `xl` | `lg` | `md`) that sets `max-w-(--breakpoint-*)`.
- `Header` fetches `settings` and `layout` singletons and passes nav/logo/CTA to `Navbar`.
- `Footer` uses `FooterHeading`, `FooterLinkBlock`, `FooterMultiColumn` slices rendered via its own `SliceZone`.

### Styling

Tailwind CSS v4 — configured via CSS (`src/app/globals.css`), not `tailwind.config.js`. Theme switching (light/dark) uses `next-themes`. shadcn/ui components are in `src/components/ui/` and should not be manually restructured.

### Environment Variables

| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_GA4_MEASUREMENT_ID` | Google Analytics 4 |
| `NEXT_PUBLIC_CLARITY_ID` | Microsoft Clarity |
| `NEXT_PUBLIC_FACEBOOK_PIXEL_ID` | Facebook Pixel |
| `NEXT_PUBLIC_VERCEL_ENV` | Set to `production` to activate analytics |
| `RECAPTCHA_SECRET_KEY` | Server-side reCAPTCHA v3 validation for the Form slice |
